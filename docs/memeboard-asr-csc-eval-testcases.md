# 语音纠错（ASR → CSC）评测测试用例

> 背景：评估「端侧 LLM 纠错 → 专用 CSC 模型（MacBERT4CSC）」替换方案的 Step 0 评测集。
> 采集器已实现（`link/AsrEvalCollector.kt`），调试期默认开启，每条语音识别写一行 JSONL：
> `{ts, raw(ASR原文), context(前文), mode, llmRaw(LLM原始输出), output(最终上屏)}`。
> 本文档是**人工标注用的 ground truth（期望正确文本）**，与 JSONL 按时间顺序对齐。

## 测试方法

1. 每条**说一遍**，自然语速，单独一句；说完等上屏结果再下一条。
2. 按编号顺序说，JSONL 行序即编号序；若有重说/漏说，记录一下。
3. 本文档的「期望文本」= 你**本来想说的**正确句子（ground truth），不是 ASR 输出。
4. 若某条识别出来是**拼音级误听**（如 d/z、n/l 声母错、听错词），也保留样本——但这类
   属于 ASR 误听，不在「同音字纠错」范围内，标注时单独归为「纠错不该管」。

## 纠错范围边界（先明确）

- ✅ 纠错管：**拼音对、字错**的同音/近音字（睡觉→水饺、晚安→网安）。
- ❌ 纠错不管：拼音级误听（d/z 声母、整词听错）——`AsrRescore` 对含英文/数字的句子也直接跳过。

## 采集后处理

```bash
# 拉取样本（debug 包）
adb exec-out run-as org.fcitx.fcitx5.android cat files/asr_eval/samples.jsonl
# 清理（评测完）
adb exec-out run-as org.fcitx.fcitx5.android rm files/asr_eval/samples.jsonl
```

每行 JSONL 对齐本文档编号后，标注三件事：

1. `raw`（ASR 原文）对不对？
2. `output`（最终上屏）对不对？——对：正确纠错/正确保留；错：漏纠 or 过度纠。
3. 若 `llmRaw` 存在且与 `raw` 不同：LLM 想改什么、改对了吗？

汇总即可得到当前 LLM 纠错的 **precision / recall**，以及「声调歧义类」占比——这是决定
MacBERT4CSC 是否值得上的核心依据。
